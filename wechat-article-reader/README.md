# wechat-article-reader

抓取微信公众号文章为本地 Markdown。正文转成纯文本格式，图片下载到本地，方便 agent 阅读。

## 工作原理

微信检测到非浏览器环境时会返回"环境异常"验证页，不给正文。本工具不伪造请求，而是驱动本机真实的 Chrome，配合持久化浏览器档案（`scripts/_wx_profile/`），让风控看到的访问和正常用户一致。页面渲染完成后从 DOM 提取正文，转成 Markdown。

## 环境要求

- 桌面操作系统（Windows / macOS / Linux）
- 已安装 Chrome，脚本通过 `channel="chrome"` 驱动系统浏览器
- [uv](https://docs.astral.sh/uv/)（依赖管理）

## 快速开始

```powershell
uv sync                                  # 首次运行，按 uv.lock 还原环境
uv run scripts/wechat_reader.py "<文章URL>"
```

输出在当前工作目录下：

```
公众号文章/<发布日期>-<标题>.md   正文，头部带 YAML frontmatter（标题、公众号、作者、日期、原文链接）
公众号文章/images/                文章的配图
```

## 常见问题

- 首次运行或换新机器后抓取失败：微信对新环境必拦。加 `--headed` 跑一次，在弹出的窗口里手动完成验证。信任会话会写入 `_wx_profile/`，之后这台机器长期免验证。
- 用了一段时间后又开始被拦：会话过期，同样加 `--headed` 重过一次验证。
- 公众号名或作者字段为空：微信新版文章模板是异步渲染的，脚本已做等待和多选择器兜底，新旧模板都能取到。个别页面仍为空，是页面本身没有这个字段。
- 图片过几天打不开：不会发生，抓取时图片已全部下载到本地。微信图片有防盗链，远程 URL 会过期，所以不要跳过本地化直接存图链。
- 原文被作者删除：不影响，本地 Markdown 是完整快照，source 字段只是溯源留档。
- 抓下来的原始 Markdown 带赞赏、按钮、推广链接等内容：这是有意的分工。脚本只负责把正文连图拿下来并做长度自检（提取异常会直接报错），内容清洗由 agent 按 SKILL.md 的"清洗要求"完成。不做规则式清洗是因为公众号模板差异太大，规则容易失效，而 agent 判断哪段是正文不会失效。
- 批量抓取多篇：链接之间间隔 10 秒以上，避免触发频率风控。
- 在服务器（数据中心 IP）上运行，暂未解决：机房 IP 被拦概率高，触发验证也没人在场处理。目前可行的做法是把它部署在住宅网络的常开机器上包成服务，服务器上的 agent 远程调用。这个适配还没做。
- 在无 Chrome 的纯 Linux 服务器上运行，暂未解决：脚本依赖系统 Chrome 的浏览器指纹，换成 Playwright 自带 Chromium 会明显提高被拦概率，需要改造后重新验证效果。
